# AGENTS.md — Правила ИИ-агентов по работе с внешними данными

> Обязательная процедура проверки свежести веб-данных для любого ИИ-агента
> (чат, кодовый агент, techwriter), обращающегося к внешним ресурсам
> экосистемы НП «Общественное благополучие».

## 1. Термины

- **Снимок (кэш)** — сохранённая промежуточным слоем копия страницы; может
  возвращаться вместо живых данных, в т.ч. после изменения или удаления
  ресурса.
- **Источник правды** — данные пользователя (скриншоты, вставленное
  содержимое, вывод `git log`, `ls`, `cat`) либо эндпоинты с абсолютными
  датами (GitHub API).
- **Свежесть** — соответствие данных текущему моменту, подтверждённое
  минимум двумя независимыми эндпоинтами (§3).

## 2. Базовый принцип

Любое веб-извлечение — потенциально снимок. Факт о внешнем ресурсе
считается непроверенным до подтверждения свежести по §3.

## 3. Процедура верификации (GitHub)

Перед утверждением факта о репозитории/файле/коммите получить:
1. `GET api.github.com/repos/<owner>/<repo>` — существование репозитория;
2. `GET api.github.com/repos/<owner>/<repo>/commits?per_page=1` — последний
   коммит с абсолютной ISO-датой;
3. `GET raw.githubusercontent.com/<owner>/<repo>/<branch>/<path>` — файл;
4. HTML-страница — только как дополнительный источник.

Правила решения:
- API = 404 → ресурс удалён или история переписана; «контент» из других
  эндпоинтов — кэш; не представлять его текущим.
- Относительное время HTML не сходится с абсолютной датой API / текущей
  датой → HTML — снимок.
- Два запроса в разное время побайтово идентичны (включая относительное
  время) → кэш.
- Эндпоинты расходятся → сообщить о расхождении, не выбирать сторону
  без оснований.

Обход кэша (если доступен): уникальный параметр `?nocache=<timestamp>`.

## 4. Иерархия источников правды

1. Данные пользователя (скриншоты, вставки, локальный git).
2. GitHub API (абсолютные даты).
3. raw.githubusercontent.com.
4. HTML-страница.

Вышестоящий источник отменяет нижестоящий при конфликте.

## 5. Маркировка утверждений

Каждый факт из веба сопровождается: URL/эндпоинт, наблюдаемая дата,
уровень доверия: «проверено» (по §3) или «вероятно кэш».

## 6. Поведение при расхождениях

- Не придумывать объяснения задним числом. Неизвестно → «не знаю» +
  проверяемые гипотезы + способ их различить.
- Пользователь указал на расхождение → признать, перепроверить по §3,
  скорректировать вывод. Не защищать прежнее утверждение.

## 7. Поддержка документа

- Изменения правил — только PR с инкрементом версии во frontmatter.
- Короткая версия правил живёт в Custom Instructions ИИ-платформы;
  при изменении настоящего документа синхронно обновляется и она.
- Ссылка на настоящий файл — в README репозитория.
