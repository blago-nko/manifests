## 4. Стратегия

**Одно правило = одна фаза = одна ветка = один PR.**
Два допустимых способа устранения:

- **FIX** — правка контента (предпочтительно);
- **TUNE** — параметризация правила в `.markdownlint.yaml`, если правка
  контента ломает семантику (якоря, пермалинки, нумерацию доменов).
  Выбор TUNE обязан быть обоснован в PR фазы.

Запрещено: смешивать фазы в одном PR; вносить содержательные изменения
манифестов под видом чистки; отключать правила целиком вместо FIX/TUNE.

## 6. Регламент фазы (workflow)

1. Контрольный прогон линтера, актуализация счётчика ошибок фазы.
2. Ветка `chore/SAM-CHORE-002-md0XX` от `main`.
3. Правки + возврат правила в `.markdownlint.yaml`.
4. PR с заголовком `[SAM-CHORE-002] Фаза N: MD0XX — <способ>`, ссылка на
   настоящий протокол, заполненный PR template.
5. Approve Архкомитета → merge (squash).
6. Коммит `chore: SAM-CHORE-002 — фаза N завершена` с отметкой в разделе 7.
