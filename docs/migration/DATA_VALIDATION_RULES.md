# Правила валидации данных миграции (Data Validation Rules)

**Версия:** 1.0  
**Дата:** 2026-09-26  
**Статус:** Обязательный для CI Pipeline  

## Цель
Предотвратить попадание в продакшн неполных, искаженных или SEO-недружественных артефактов после экспорта из Blogger.

## 1. Обязательные поля Front Matter
Каждый Markdown-файл в папке `content/posts/` должен содержать следующие поля:

| Поле | Тип | Требования | Дефект (Fail) |
| :--- | :--- | :--- | :--- |
| `title` | String | Непустая строка. Уникальна в рамках сайта. | `""`, `"Untitled"`, `"New Post"`. |
| `date` | ISO8601 | Соответствует оригинальной дате публикации. Год >= 2010. | `1970-01-01`, `null`, дата в будущем без `draft: true`. |
| `author` | String | Имя автора или никнейм из `data/authors.yaml`. | `""`, `"Anonymous"`, отсутствие поля. |
| `description` | String | Длина 50–160 символов. Используется для SEO meta и JSON-LD. | Пусто, длина < 30 или > 200, дубликат с другим постом. |
| `tags` | Array[String] | Массив строк. Совпадает с глобальной таксономией (САМ.md). | Опечатки (`"новости"` vs `"Новости"`), пустой массив (если не допустимо). |
| `blogger_url` | String | Оригинальный URL на платформе Blogger. Нужен для 301 редиректов. | Отсутствие поля, невалидный формат URL. |

## 2. Запрещенные значения и паттерны
CI-скрипт должен блокировать мердж, если найдены:
*   **Placeholder Dates:** `1970-01-01T00:00:00Z`, `0001-01-01`.
*   **Generic Descriptions:** `"Post description"`, `"Read more"`, `"Click here"`.
*   **Broken Images:** Вызовы шорткода `{{< img >}}` без атрибута `alt`.
*   **HTML Artifacts:** Остатки тегов Blogger (`<div class="post-body">`, inline стили `style="..."` внутри Markdown тела поста).

## 3. Проверка медиа-контента
*   Все изображения должны быть загружены через шорткод `{{< img src="..." alt="..." >}}`.
*   Внешние ссылки (Blogger CDN) допускаются на этапе пилота, но помечаются тикетом для локализации в `static/images/` на Этапе 3.
*   Атрибут `loading="lazy"` должен присутствовать во всех изображениях ниже первого экрана (контролируется темой, но проверяется в output HTML).

## 4. Автоматизация (CI Integration)
В workflow GitHub Actions каждого сайта добавить шаг "Validate Data Integrity".
Этот шаг должен запускать скрипт `scripts/validate_data_integrity.py` с аргументом директории контента (`--dir content/posts/`).

Скрипт `validate_data_integrity.py` должен возвращать код выхода `1` (fail), если нарушено любое правило раздела 1 или 2.

## 5. Процесс исправления дефектов
Если CI падает:
1.  Логи показывают конкретный файл и поле.
2.  Разработчик вручную правляет Front Matter в Markdown-файле.
3.  Повторный пуш запускает проверку снова.
4.  Если проблема массовая (например, все посты имеют пустой `author`), инициируется повторный запуск скрипта `blogger_export.py` с фиксом маппинга авторов.
